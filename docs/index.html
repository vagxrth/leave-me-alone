Indian D2C · identity tracking

Leave Me Alone

Shops you have never logged into already know your phone number. Find out which ones, then stop it happening again.

A single vendor's login module runs on a large share of Indian D2C storefronts. Every one of them embeds a hidden frame from the same shared origin, and that frame carries one persistent user id and one stored phone number between them all — writing both into each shop's own storage.

The effect is that a shop you have never given anything to can recognise you on your first visit, and pass what you looked at to a WhatsApp campaign tool. You can check this on yourself in about ten seconds.

01See what a shop already knows

Open any Indian D2C store, then run the scanner on it. It reads only that page's own storage, shows you the result, and sends nothing anywhere.

Reading the result

phone
The number that shop currently holds for you, decoded from a key named notifyph. It is stored as base64, which is an encoding, not encryption.
networkId
Your id across the whole network. Run the scanner on a second, unrelated shop — it is the same value.
networkVisits
How many shops in the network have seen you. This is the number that tends to surprise people.
thisShop
How many times you have visited this particular shop. A 1 next to a phone number means it identified you on your first ever visit.

02Block it

Five rules. They stop the identity sync, the fingerprinting and the event collectors, and they deliberately leave cart and payment alone so you can still buy things.

Add to uBlock Origin / AdGuard

If that button does nothing, add it by hand: uBlock Origin → Dashboard → Filter lists → Import → paste the URL below.

https://vagxrth.github.io/leave-me-alone/gokwik.txt

The stronger move, which costs nothing

Do your shopping in Firefox, Brave or Safari. All three partition third-party frame storage by default, which breaks the mechanism structurally rather than one hostname at a time — and it covers networks this list does not know about. Chrome does not do this.

03Get the record deleted

Blocking stops new collection. It does not remove what is already held — that takes a written request, and under India's DPDP framework you are entitled to make one.

A template is in the repository: erasure-letter.md. Run the scanner first, so you can name your own network id in the letter. A request that quotes the identifier is much harder to answer with a form reply.

04What this does not do

  • It does not undo existing exposure. If your number is already in the network, shops that have it can still message you. Blocking stops the next shop learning it.
  • It does not cover every vendor. This list covers one network, the largest one. Others operate on the same storefronts.
  • It is not a privacy suite. Analytics, session recording and ad pixels are untouched. Use this alongside a general privacy list, not instead of one.
